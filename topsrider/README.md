# 燧原 TopsRider

> 燧原科技邃思系列 AI 加速器的软件平台，面向训练集群与推理部署，提供图编译与算子开发能力。

## 基本信息

| 项目 | 内容 |
|---|---|
| 主导方 | 燧原科技（Enflame） |
| 首次公开 | 2021 发布 TopsRider 软件平台（配合邃思 2.0） |
| 类型 | AI 加速器软件栈 |
| 开闭源 · 许可 | 闭源 SDK |
| 核心语言 / 接口 | 图编译器 + 自定义算子（C/C++）、PyTorch / ONNX 前端 |
| 需要硬件 | 邃思（DTU）系列训练/推理卡 |
| 当前状态 | 商用中，主要服务政企与智算中心 |

## 设计思路

TopsRider 采用「**编译器为主**」的路线：用户提供 ONNX 或 PyTorch 模型，平台负责算子切分、量化、内存规划与多卡通信编排，最终生成针对邃思硬件的执行包。只有编译器覆盖不到的算子才需要手写。

训练侧提供分布式训练组件（数据并行、张量并行），推理侧提供量化与服务化工具链。

## 最小示例

```bash
# 典型链路：模型转换 → 编译 → 部署
topsrider compile --input model.onnx --output model.tops --precision int8

# Python 侧加载执行（示意）
```

```python
import topsrider as ts

runtime = ts.Runtime("model.tops")
outputs = runtime.run(inputs)
```

## 与其它方案的异同

- **vs CUDA**：完全不同的栈，无源码级兼容，迁移需要走模型转换。
- **vs CANN**：定位接近（国产 AI 加速器 + 图编译器），CANN 生态与文档更成熟。
- **vs MagicMind**：同为推理图编译器，MagicMind 更偏 CV 推理，TopsRider 强调训练集群。
- **vs TVM**：TopsRider 闭源且绑定硬件，TVM 开放但需要自行做后端适配。

## 优势

- 面向训练集群设计，支持多卡多机扩展。
- 图编译 + 量化一体化，部署链路较完整。
- 国产化方案，适合智算中心与政企项目。
- 与国内云厂商有合作落地。

## 局限

- 闭源，调试与性能分析完全依赖厂商。
- 社区几乎为零，公开资料极少。
- 算子覆盖依赖编译器，新模型适配需要时间。
- 主要靠项目制交付，开发者自助体验差。
- 生态工具链（Profiler、调试器）成熟度不足。

## 现状与生态

主要通过智算中心、政企项目落地，开发者通常由厂商工程师配合完成部署。个人开发者与开源社区几乎接触不到。选型时务必要求厂商提供目标模型的端到端实测与支持承诺。
